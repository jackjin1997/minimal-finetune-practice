先理解两个概念：微调和 LoRA

Two Concepts First: Fine-Tuning and LoRA

先把词讲清楚，再跑命令。微调是目标：让模型更擅长某个任务行为。LoRA 是一种实现方式：用很少的可训练参数完成这个目标。

Clarify the terms before running commands. Fine-tuning is the goal: make a model better at a specific task behavior. LoRA is one way to do it: train a small number of adapter parameters.

微调是什么

What is fine-tuning?

微调就是拿一个已经训练好的基础模型，用你自己的小数据再训练一小段，让它更倾向某种固定任务、格式或表达风格。

Fine-tuning means taking an already trained base model and training it a bit more on your own data so it prefers a specific task, format, or style.

LoRA 是什么

What is LoRA?

LoRA 是 Low-Rank Adaptation。它冻结基础模型，只训练一小组 adapter 参数；推理时把 base model 和 adapter 一起加载。

LoRA means Low-Rank Adaptation. It freezes the base model and trains a small adapter; at inference time, the base model and adapter are loaded together.

LoRA 的生态位：它解决哪一类问题

LoRA's Niche: What Problem It Solves

LoRA 不是产品，也不是“让模型变聪明”的唯一办法。它的位置是：当 prompt 已经不够稳定、RAG 又解决不了行为问题、全量微调又太贵时，用少量参数把模型行为往目标任务推。

LoRA is not a product, and it is not the only way to improve a model. Its niche is behavior adaptation when prompting is not stable enough, RAG does not solve the behavior problem, and full fine-tuning is too expensive.

Prompt

Prompting

不训练模型，只写更好的 system/user prompt。最便宜，适合轻量约束；但复杂格式可能不稳定。

No training. Improve system/user prompts. Cheapest option, good for light constraints, but complex formats can remain unstable.

RAG

RAG

不改变模型权重，把外部文档检索出来放进上下文。适合知识更新，不适合强行改变输出习惯。

Do not change weights. Retrieve external documents into context. Good for changing knowledge, not for deeply changing output habits.

工具调用 / 约束解码

Tools / constrained decoding

在推理时强制模型调用函数或满足 JSON schema。适合强格式保证，常和 prompt 或 LoRA 搭配。

Force function calls or JSON schema at inference time. Useful for hard format guarantees, often combined with prompting or LoRA.

LoRA / QLoRA / DoRA

LoRA / QLoRA / DoRA

参数高效微调。适合固定格式、分类、抽取、风格和领域流程。Mac 本地练习优先选它。

Parameter-efficient fine-tuning. Good for fixed formats, classification, extraction, style, and domain workflows. A good default for Mac practice.

全量微调

Full fine-tuning

训练更多甚至全部权重。能力上限高，但成本、数据要求和灾难性遗忘风险也更高。

Train many or all weights. Higher ceiling, but higher cost, data requirements, and risk of catastrophic forgetting.

偏好优化

Preference optimization

如 DPO/ORPO/GRPO，更偏向“哪个回答更好”的对齐阶段，通常在 SFT/LoRA 之后考虑。

Methods like DPO, ORPO, and GRPO optimize which answer is preferred, often after SFT/LoRA.

本项目选 LoRA 的原因：我们不是要补知识，而是要让模型稳定执行“需求 -> JSON”的行为；同时只有 Mac，本地成本要低。
This project uses LoRA because the goal is not new knowledge; it is stable “request -> JSON” behavior, with a low-cost local Mac setup.

微调原理：这次到底训练了什么

Fine-Tuning Principle: What Changed

这次不是把一批知识塞进模型，而是用样本把模型的输出行为往“只输出固定 JSON schema”这个方向推。base model 保持不变，LoRA adapter 学会任务偏好。

We are not stuffing facts into the model. We are using examples to push the output behavior toward a fixed JSON schema. The base model stays frozen, and the LoRA adapter learns the task preference.

用 loss 理解训练

Understanding Training Through Loss

训练时，模型看到 system + user，并尝试预测 assistant 的 JSON。预测越接近期望答案，loss 越低。`--mask-prompt` 的作用是只让 assistant 输出部分参与主要优化，避免模型把输入提示本身也当成学习目标。

During training, the model sees system + user and predicts the assistant JSON. The closer the prediction is to the target answer, the lower the loss. `--mask-prompt` focuses optimization on the assistant output instead of also learning the input prompt.

但 loss 低不等于一定好。我们 240 step 时训练 loss 很低，验证和测试反而变差，这就是小数据过拟合。最终选择 100 step，是因为验证、测试和未见样例更一致。

Low loss is not automatically good. At 240 iterations the train loss was very low, but validation and test got worse: overfitting on tiny data. We kept 100 iterations because validation, test, and unseen generation were more consistent.

Step by Step: Run the Loop

每一步都回答一个问题。不要跳过 baseline、test 和未见样例，它们分别帮助你判断“原模型问题是什么”“adapter 有没有学到”“有没有只是背测试样例”。
