读完应该学会什么

What You Should Understand

这不是一个展示页，而是一条最小学习路线。读完并跑完命令后，你应该能解释微调为什么有效、什么时候该微调、每一步在验证什么。

This is a learning path, not just a showcase. After reading and running the commands, you should be able to explain why fine-tuning works, when to use it, and what each step verifies.

原理

Principle

LoRA 冻结 base model，只训练少量 adapter 参数，让模型更倾向某种输出行为。

LoRA freezes the base model and trains a small adapter so the model prefers a target behavior.

步骤

Steps

baseline、数据校验、训练、test、未见样例验证，每一步都有不同目的。

Baseline, data validation, training, test, and unseen generation each answer a different question.

判断

Judgment

loss 下降不等于产品可用；要看验证集、测试集和未见样例是否一致。

Lower loss is not enough. Validation, test, and unseen prompts must tell a consistent story.

边界

Boundary

微调适合稳定格式和行为，不适合当实时知识库；知识更新更适合 RAG 或工具。

Fine-tuning fits stable formats and behavior. Dynamic knowledge is usually better handled by RAG or tools.

为什么选这个场景

Why This Scenario

它不需要大数据，也不需要复杂评测；只要看 JSON 是否有效、字段是否齐全、枚举和日期是否正确，就能判断模型行为是否被推向目标。

It does not need a large dataset or a complex benchmark. Valid JSON, complete fields, constrained enum values, and correct date extraction are enough to judge whether the model behavior moved in the right direction.

目标清晰

输入是一句话需求，输出是固定任务卡 JSON。

字段、枚举、日期、owner 都可以直接检查。

Clear Target

Direct Feedback

Small-Model Friendly

微调原理：这次到底训练了什么

Fine-Tuning Principle: What Changed

这次不是把一批知识塞进模型，而是用样本把模型的输出行为往“只输出固定 JSON schema”这个方向推。base model 保持不变，LoRA adapter 学会任务偏好。

We are not stuffing facts into the model. We are using examples to push the output behavior toward a fixed JSON schema. The base model stays frozen, and the LoRA adapter learns the task preference.

+
LoRA adapter LoRA adapter 只训练 2.884M 参数，占 596.050M 参数的 0.484%。 Only 2.884M trainable parameters, 0.484% of 596.050M total parameters.

目标行为 Target behavior 更稳定地产生 JSON、字段、枚举、日期和简短摘要。 More stable JSON, fields, enum values, dates, and concise summaries.

用 loss 理解训练

Understanding Training Through Loss

训练时，模型看到 system + user，并尝试预测 assistant 的 JSON。预测越接近期望答案，loss 越低。`--mask-prompt` 的作用是只让 assistant 输出部分参与主要优化，避免模型把输入提示本身也当成学习目标。

During training, the model sees system + user and predicts the assistant JSON. The closer the prediction is to the target answer, the lower the loss. `--mask-prompt` focuses optimization on the assistant output instead of also learning the input prompt.

但 loss 低不等于一定好。我们 240 step 时训练 loss 很低，验证和测试反而变差，这就是小数据过拟合。最终选择 100 step，是因为验证、测试和未见样例更一致。

Low loss is not automatically good. At 240 iterations the train loss was very low, but validation and test got worse: overfitting on tiny data. We kept 100 iterations because validation, test, and unseen generation were more consistent.

Step by step：从零跑一遍

Step by Step: Run the Loop

每一步都回答一个问题。不要跳过 baseline、test 和未见样例，它们分别帮助你判断“原模型问题是什么”“adapter 有没有学到”“有没有只是背测试样例”。

Each step answers one question. Do not skip baseline, test, or unseen generation: they tell you what the base model fails at, whether the adapter learned, and whether it merely memorized the test sample.

0

先定义任务边界

Define the task boundary

本项目只训练“自然语言需求 -> 固定 JSON”。这让结果可检查，也避免把微调误用成知识库。

This project only trains “task request -> fixed JSON”. The result is easy to inspect, and it avoids treating fine-tuning as a knowledge database.

准备 Mac 环境

Set up the Mac environment

创建虚拟环境并安装 `mlx-lm`。如果 Python 版本较旧，可能会安装兼容的旧版 `mlx-lm`。

Create a virtual environment and install `mlx-lm`. Older Python versions may resolve to an older compatible `mlx-lm`.

command 
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
2

校验训练数据

Validate the dataset

先保证 JSONL、schema、枚举、日期格式和 system prompt 一致。数据不稳，训练结果一定不稳。

Check JSONL, schema, enum values, date format, and system prompt consistency first. Unstable data produces unstable training.

command 
make check-data

valid.jsonl: 4 samples
test.jsonl: 4 samples

跑 baseline，先看原模型

Run the baseline first

baseline 告诉你“为什么要微调”。本次原模型会输出 `` 和解释，没有稳定只输出 JSON。

The baseline tells you why fine-tuning is needed. Here the base model emitted `` and explanations instead of stable JSON only.

command 
HF_ENDPOINT=https://hf-mirror.com make baseline
4

训练 LoRA adapter

Train the LoRA adapter

只训练 adapter，不改 base model。`--mask-prompt` 让训练主要关注 assistant JSON 输出。

Train only the adapter, not the base model. `--mask-prompt` focuses training on the assistant JSON output.

command 
HF_ENDPOINT=https://hf-mirror.com make train
5

用 test loss 检查泛化方向

Use test loss to check generalization

训练 loss 只能说明模型贴近训练集；test loss 更能提醒你是否过拟合。这里 240 step 过拟合，100 step 更稳。

Train loss only shows fit to the training set. Test loss is better at warning about overfitting. Here 240 steps overfit, while 100 steps was more stable.

result 
Test loss 0.240, Test ppl 1.272
6

最后用未见样例验证

Verify with an unseen prompt

不要只用测试集同款 prompt 展示效果。`generate-unseen` 用不在 train/valid/test 的输入，看模型是否真的学到 schema 和分类规则。

Do not showcase only a test-like prompt. `generate-unseen` uses an input outside train/valid/test to check whether the model learned the schema and classification rules.

command 
HF_ENDPOINT=https://hf-mirror.com make generate-unseen

当前结果

Current Result

同步 data 和 prompts 的 system prompt 后，使用 `--mask-prompt` 训练 100 step，当前结果如下。它已经完成最小学习目标，但还不是产品级模型。

After synchronizing the dataset system prompt with `prompts/system.txt`, the adapter was trained for 100 iterations with `--mask-prompt`. This completes the learning goal, but it is not a production model.

34samples / 样本总数

1.272test ppl

关键学习点：240 step 在小数据上过拟合；补边界样本并使用 100 step 更稳。下一轮应继续补数据，而不是继续加训练步数。

Key lesson: 240 iterations overfit this tiny dataset. Adding boundary samples and training for 100 iterations was more stable. The next improvement should be more data, not simply more steps.
