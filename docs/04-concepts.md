# 04. 概念笔记

## 微调学什么

微调主要让模型学习某类输入到输出的行为映射。

在这个项目里，模型要学的是：

- 只输出 JSON。
- 固定字段。
- 识别任务类型。
- 识别优先级。
- 从文本里抽取日期和负责人。
- 用稳定短句总结需求。

它不是把业务知识永久、可靠地塞进模型。需要频繁更新的知识，更适合 RAG 或工具查询。

## LoRA 是什么

LoRA 的核心思路是冻结原模型大部分权重，只训练少量低秩适配参数。

直觉上可以理解成：

- base model 是通用能力底座。
- adapter 是针对某个任务的行为补丁。
- 推理时把 base model 和 adapter 一起加载。

好处：

- 训练显存/内存要求低。
- 训练产物小。
- 可以为不同任务保留不同 adapter。

代价：

- 它不是全量重训。
- 数据质量差时，adapter 会很快学歪。
- 小数据更容易过拟合固定措辞。

## 为什么不从大模型开始

入门微调时，优先选择小模型，因为学习重点是流程：

1. 数据格式是否正确。
2. baseline 是否可观察。
3. 训练是否能跑完。
4. adapter 是否能加载。
5. 输出是否有方向性变化。

这些都跑通后，再换更大模型才有意义。

## 大小模型不是只有数据量区别

参数量更大的模型通常也会使用更多训练数据和算力，但差异不只在数据量。

关键差异包括：

- 参数量：模型能表达的模式容量。
- 架构：层数、注意力结构、MoE、归一化、位置编码、上下文长度。
- tokenizer：中文、代码、多语言文本的切分效率。
- 训练阶段：预训练、指令微调、偏好对齐都会改变行为。
- 数据配比：代码、数学、中文、多语言、合成数据比例会影响能力分布。
- 推理设置：量化、上下文长度、KV cache、chat template 都会影响实际效果。

所以“模型更大”不是“只是数据更多”，而是底座容量、训练方法和推理形态一起变化。

## 什么时候该微调

适合微调：

- 固定输出格式。
- 固定语气风格。
- 重复性分类、抽取、改写。
- 某个领域的稳定工作流。

不优先微调：

- 需要实时知识。
- 数据每天变。
- 问答依据必须可追溯。
- 只是想让模型知道一批文档内容。

这些更适合 RAG、数据库查询或工具调用。
